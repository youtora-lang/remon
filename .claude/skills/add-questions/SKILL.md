# remon 問題追加

## 範囲

PRELOAD への問題追加だけを扱う。単元枠の新設・改名・削除、UIの変更、データ構造の変更は対象外。必要だと判断した場合は手を止めて相談する。

## 1バッチの定義

- 各教科の続きから2単元ずつ、1単元あたり6〜7問
- 過去のバッチの規模は、10単元67問（各教科2単元ずつ）程度
- 1バッチごとに検証とコミットまで畳んでから次へ進む。複数バッチをまとめて1コミットにしない

## 追加先の選び方

1. index.html の `PRELOAD` から、問題数が0の単元（準備中枠）を教科ごとに先頭から拾う
2. 単元名は PRELOAD にある文字列をそのまま使う。1文字でも変えると別の枠になる
3. 新しい単元枠は作らない
4. 既存単元へは末尾に追加する。既存の問題文はむやみに書き換えない（学習履歴は配列内の位置で保存されており、問題文はキーではない。ただし syncPreload が作り直しのときに問題文を仲立ちに履歴を張り直すため、問題文を変えるとその問題は新しい問題として扱われ、正誤記録と復習タイミングが初期化される）

各教科2単元ずつが基本。ただし**空き枠が尽きた教科は飛ばし、残っている教科から補って1バッチ12単元を保つ**。教科ごとの空き枠数は不均一なので、後半ほど特定の教科に寄る。

**全教科の空き枠が尽きたあとは、既存単元に問題を足す。** 1単元6〜7問のところを10問程度まで増やす。追加は末尾に足し、既存の問題文は書き換えない。

本文が必要で飛ばした単元は、**準備中のまま残す**。教科書の本文を渡されたときに作る枠として扱う。

## 配当時間のない教材は載せない

教科書の年間指導計画で配当時間が割り当てられていない教材には、問題を作らない。授業で扱わない以上、定期テストの範囲にならないため。

ただし時数のない枠は PRELOAD から落としてあり、新しい単元枠も作らないので、**追加のたびに時数を調べ直す必要はない**。PRELOAD に枠があるものは、すべて作ってよい単元。

## 本文がないと作れない単元

- **英語の Unit 系**：単元名の括弧に文法項目が書かれていれば（例: `Unit 4 … P3（命令文 Come/Be/Don't）`）、教科書本文がなくてもその文法項目に沿って作ってよい。本文の細部は問わない。括弧がなく本文の内容にしか手がかりがない単元は飛ばす
- **国語の教材文系**：本文にしか書かれていないことは問わない。本文の外でも確かめられること（ジャンル、読み方、作者、題材、広く知られた枠組み）だけを問う。それでも作れないものは飛ばす

飛ばすときは、その単元は教科書の本文が必要だと報告して次の候補へ進む。

## データ形式

- 1問は `{question, choices, explanation}` の3キーのみ
- `choices` は4つ。**正解は `choices[0]`** という位置の約束で、正解フラグもIDも難易度も持たない
- 出題時のシャッフルはアプリ側で行うので、データ側は常に先頭が正解
- `explanation` は、なぜその答えになるかが短く分かる日本語にする
- 誤答の選択肢は、教科書の範囲でありそうな間違いにする。明らかに不自然なものを混ぜない
- 選択肢の長さを揃えるときは、冗長な言い換えや括弧の補足を削る。正解が成り立つために必要な条件は削らない

## 表記

CLAUDE.md 項目7・8 に従う。要点は次の2つ。

- 数式・座標に使う記号は半角にする（`=` `-` `+` `(` `)`）。全角を使うのは「面積＝底辺×高さ÷2」のように日本語の文章として書く場合だけ
- `=` まわりの空白は単元内の統一を優先し、新規は空白なしを既定とする

## 重複

- 同じ教科内に、ほぼ同じことを問う問題を作らない。追加前にその教科の既存問題を確認する
- validate-questions.js は重複を「教科/単元/単元内の問題番号」で報告する（PRELOAD が1行のため行番号は役に立たない）

## 仕上げ（この順番で）

1. `node validate-questions.js` が全項目パス（終了コード 0）。落ちたら直して再実行する
2. フッターの Updated を日本時間で更新する
3. sw.js の `CACHE_NAME` を1つ上げる（上げないと Service Worker の更新が発火せず、端末に反映されない）
4. `git add` はファイルを明示する（`-A` は使わない）
5. commit する。メッセージは40文字以内、`Co-Authored-By` 行は入れない（公開リポジトリのため）
6. push は指示があってから。自分の判断で push しない

`PRELOAD_STRUCT_VERSION` は上げない（上げるのは単元枠の増減・改名のときだけ）。README には問題数や単元の埋まり具合のような変動する数字を書かない。

## 完了時に報告すること

- 追加した教科・単元名・問題数
- 追加後の総問題数と、問題ありの単元枠数
- validate の結果、新しい `CACHE_NAME`、フッターの Updated
- 次のバッチで埋める候補（教科と単元名）
