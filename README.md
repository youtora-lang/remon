# remon

中学1年生向けの5教科テスト対策学習アプリ（PWA）。
教科書に準拠した4択クイズを、間隔反復（忘れたころに復習）で出題する。

ビルド不要の静的サイト。index.html にUI・ロジック・問題データがすべて入っている。

## 名前の由来

`re`（繰り返す）＋ `mon`（問題）で「remon」。
繰り返し問題を解いて定着させる、というアプリの狙いをそのまま名前にしている。

## 主な機能

### 学習

- **今日の 20 remon**：全教科から、復習どきの問題と未学習の問題を中心に20問出題
- **今日の remon**：教科ごとに、間隔反復で出すべき問題を出題
- **単元を選ぶ**：単元を指定してまとめて練習
- **まちがえた問題を復習**：直前の回で間違えた問題だけをもう一度
- 4択はすべて教科書準拠。誤答にはよくある誤解・ミスを仕込み、解説で正誤の理由を示す

### 進捗管理

- 単元行の2行目に「問題数・状態」を表示：未学習 / 完了 / おやすみ中（除外中）、
  問題が入っていない枠は「準備中」。復習どきの単元だけは文字に埋めず、
  単元名の太字・左の色帯・右の🔔で示す
- 単元ごとのボタンで「今日の出題対象」から外せる（テスト範囲の絞り込みに利用）
- 単元の選択状態は解除するまで保持される
- ホーム画面に教科ごとの学習進捗（学習済み問題数・正答率）を表示
- 週間バーチャート（目標達成日は緑、未達成はオレンジ、今日は枠付き）

### データの保存と読み込み

- **データ保存**：学習状況をJSONファイルとして書き出す（クリップボードへのコピーも可）
- **データ読み込み**：書き出したファイルから復元する。読み込む前に中身を検証し、
  壊れていれば途中で中断して現在の状態を変更しない
- バックアップに入るもの：
  `questions` / `history` / `streak` / `lastDate` / `totalCorrect` / `lemons` /
  `dailyRecords`（週間記録）/ `excludedUnits`（除外単元）/ `fontSize` /
  `dailyGoal` / `sessionSize` / `explainMode`
- 入らないもの：単元の選択状態（作業中の一時状態のため）と
  `PRELOAD_STRUCT_VERSION`（復元先の問題データに属する値のため）
- ファイルには `backupVersion` を持たせる。読み込み時、バックアップに無いキーは
  現在の値のままにするので、旧形式（6項目のみ）のファイルもそのまま読み込める

### 学習履歴の堅牢性

- 履歴は問題文をキーに保存する。問題の追加・並べ替え・構造変更があっても、
  正誤記録と復習タイミングは引き継がれる（`PRELOAD_STRUCT_VERSION` を上げても消えない）

### 画面と操作

- ホームは上部の細いバーだけを固定し、それ以外はすべてスクロールする。
  最上部ではロゴとタイトルが大きく表示され、スクロールすると縮んでバーになる
  （文字を大きくする設定でも教科一覧が隠れないようにするため）
- 教科ページもホームと同じく、上部の細いバーと下部の「はじめる」だけを固定し、
  教科名と学習モードの選択はスクロールに含める。「はじめる」には選んだ単元数と
  問題数を表示する
- スマホの戻るボタンと画面の戻るボタンは同一の動作。画面単位ではなく操作単位で
  1step戻り、ホームより手前でアプリが閉じることはない
- フッター（更新日時・Made by Chii）は各ページ下部に表示する。
  ホームではスクロールの末尾に置かれる

## データの仕組み

- `PRELOAD`：index.html 内の1行に埋め込まれた問題データ。
  `{ subject, unit, questions: [{ question, choices, explanation }] }` の配列で、
  **`choices` の先頭が正解**（正解フラグは持たない）
- `PRELOAD_STRUCT_VERSION`：単元構成を変更したら上げる。上げても学習履歴は
  問題文ベースで引き継がれる
- 学習状況は localStorage に保存する
- 問題数や単元の埋まり具合は変動するのでここには書かない。
  最新の内訳は `node validate-questions.js` の出力（先頭行）で確認する

## 問題を追加するとき

1. index.html の `PRELOAD` を編集する（既存単元への追加は末尾に足す。
   末尾追加なら既存の学習履歴に影響しない）
2. `node validate-questions.js` を実行して検証する
3. フッターの更新日時を直す
4. **sw.js の `CACHE_NAME` を上げる**（上げないとService Workerが更新されず、
   ブラウザに反映されない）
5. push する

問題の書き方・単元の区切り方は CLAUDE.md を参照。

## 検証スクリプト

```
node validate-questions.js
```

チェック項目は、必須キーの有無 / 選択肢がちょうど4個 / 同一問題内の選択肢重複 /
同一教科内の問題文重複 / 単元名の重複。
重複は「教科 / 単元 / 単元内の問題番号」で報告する（`PRELOAD` が1行のため行番号は使えない）。

終了コードは 0=全項目パス、1=違反あり、2=読み込み失敗。

合格の目安は**全項目パス（終了コード 0）**。重複が報告された場合、その問題は
アプリ側で排除されて出題されないため、解消してから push すること。

JSONの構文を壊すとアプリが白画面になるため、pushの前に必ず実行すること。
