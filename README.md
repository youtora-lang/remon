# dango

中学1年生向けの5教科テスト対策学習アプリ（PWA）。
教科書に準拠した4択クイズを、間隔反復（忘れたころに復習）で出題する。

ビルド不要の静的サイト。index.html にUIとロジック、questions.js に問題データが入っている。
リポジトリ名と公開URLは、以前の名前の remon のまま。

## 名前の由来

dango（だんご）の名前は、ピンク・白・緑の三色だんごの色から。正解をひとつずつ重ねて、ドットを集めていくアプリです。

## 主な機能

### 学習

出題の入口は、ホームの教科のタイルの2か所。上の部分を押すとその教科がすぐ始まり、
下の「単元を選ぶ」で教科ページを開く。どちらも出題数は設定の「1回の出題数」（全問も選べる）。

- **教科を押して始める**：おやすみ中の単元を除いた、その教科の問題から選ぶ
  1. 復習どき（次に出す日が今日以前、または一度も正解していない問題）を出題数の半分（切り捨て）まで。
     次に出す日の近い順
  2. 残りを未学習の問題で、教科書の順（単元の並び順、単元内の問題の順）の先頭から
  3. どちらかが足りなければもう一方で埋め、それでも足りなければ、次に出す日がまだ来ていない
     問題を日付の近い順に使う
  4. 選んだ問題を混ぜて出す。結果画面の「もう一度」は、同じ教科で選び直す
- **単元を選ぶ**：教科ページで単元を選んで出題する。おやすみ中の単元も選べる
- **まちがえた問題を復習**：直前の回で間違えた問題だけをもう一度
- 4択はすべて教科書準拠。誤答にはよくある誤解・ミスを仕込み、解説で正誤の理由を示す
- 間隔反復は、正解するたびに 1→3→7→14→30日 と間隔をのばし、不正解で1日に戻す

### 単元の管理

- 単元行の2行目に「問題数・状態」を表示：未学習 / 学習済み / おやすみ中、
  問題が入っていない枠は「準備中」。復習どきの単元は、緑の「復習どき」のラベルと
  単元名の太字で示す
- 教科ページの見出しは「○○の単元を選ぶ」。開くたびに、おやすみ中と準備中を除く
  すべての単元が選ばれた状態から始まる
- 行の左の丸で単元を選ぶ（選んだら緑の丸にチェック）。選んだ状態は保存しない。
  教科ページを開いている間だけ持ち、出題から戻ったときだけ元に戻す
- 行の右の月のボタンで「おやすみ」にする（教科を押して始めるときに飛ばす）。
  おやすみ中は月が塗りつぶされ、行が半透明になる。出題対象の管理はこれ1つ

### 記録

- **今週のがんばり**：曜日の丸7つ。1日の目標に届いた日は緑の丸、今日は緑の輪
  （届いたら丸）、それ以外は点線の輪。今日の曜日は太字。右上に連続日数と
  「今日 ○/○問」。タップすると記録画面で過去の週をさかのぼれる
- **ドットコレクション**：累計正解数から計算する（保存データは持たない）。
  正解10問で1ドット、30ドット（10個×3行）で1枚のボード。ドットは淡いピンクから
  濃いピンクへ順に濃くなり、次のドットは進み具合に応じて輪が埋まる。ボードの下に
  「あと○問で次のドット」「○枚目まで あと○ドット」と、完成したボードの枚数を出す。
  出題中は正解したときに次のドットまでの残りを出す
- 教科のタイルに、復習どきの問題の数（おやすみ中を除く。0なら「復習はなし」）と、
  一度でも解いた問題の割合を10個のドットと % で出す

### 設定

ホーム右上の歯車から開くシートにまとめている。

- 使い方ガイド / データ保存 / データ読み込み
- 文字サイズ（小・中・大）/ 1日の目標正解数 / 1回の出題数 / 解説を出すタイミング
- シートの奥の「危険な操作」に、全データのリセット（警告 → 合いことばの入力の2段階）

### データの保存と読み込み

- **データ保存**：学習状況をJSONファイル（`dango-日付.json`）として書き出す
  （クリップボードへのコピーも可）
- **データ読み込み**：書き出したファイルから復元する。ファイル名は見ないので、
  remon 時代の `remon-日付.json` もそのまま読める。読み込む前に中身を検証し、
  壊れていれば途中で中断して現在の状態を変更しない
- バックアップに入るもの（`backupVersion` を含む13キー）：
  `questions` / `history` / `streak` / `lastDate` / `totalCorrect` / `lemons` /
  `dailyRecords`（週間記録）/ `excludedUnits`（おやすみ中の単元）/ `fontSize` /
  `dailyGoal` / `sessionSize` / `explainMode`
- `lemons` は以前の「レモン」の数。画面ではもう使わず数えてもいないが、
  古い版との読み書きの互換のためにキーを残している
- 入らないもの：単元の選択状態（保存しないため）と
  `PRELOAD_STRUCT_VERSION`（復元先の問題データに属する値のため）
- 読み込み時、バックアップに無いキーは現在の値のままにするので、
  旧形式（6項目のみ）のファイルもそのまま読み込める。古いファイルにある
  `selectedUnits` や、旧「社会」の教科の履歴は読み捨てる（エラーにはしない）

### 学習履歴の堅牢性

- 履歴は「教科キー＋その教科の問題の並びの位置」で保存する。起動のたびに
  `syncPreload()` が問題データから問題の一覧を作り直し、その前後で
  「教科キー＋問題文」を仲立ちに履歴を新しい位置へ張り直す
- そのため、問題の追加・並べ替え・単元枠の変更があっても、
  正誤記録と復習タイミングは引き継がれる。問題文を書き換えた問題だけは、
  別の問題として扱われて履歴が初期状態に戻る

### 画面と操作

- 背景はピンク。カードと面はピンク・白・緑をほぼ同じ割合で使い、文字とアイコンは茶系だけ。
  アイコンは線のSVGで、絵文字は使わない（色のルールは CLAUDE.md を参照）
- 書体は、数字と英字が Poppins、日本語が Zen Maru Gothic（Google Fonts）。Service Worker が一度読んだ書体を
  キャッシュし、読めないときは端末のフォントで表示する
- 各画面は上部のバーだけを固定し、それ以外はスクロールする。教科ページは
  下部の「クリア」「はじめる」も固定
- スマホの戻るボタンと画面の戻るボタンは同一の動作。画面単位ではなく操作単位で
  1step戻り、ホームより手前でアプリが閉じることはない
- フッター（更新日時・Made by Chii）は各ページ下部に表示する。
  ホームではスクロールの末尾に置かれる

## データの仕組み

- `PRELOAD`：questions.js 内の1行に入っている問題データ。
  `{ subject, unit, questions: [{ question, choices, explanation }] }` の配列で、
  **`choices` の先頭が正解**（正解フラグは持たない）
- `PRELOAD_STRUCT_VERSION`：今は分岐に使っていない。バックアップの互換のために値だけ残している
- 学習状況は localStorage の `remon_state` に保存する（名前を変えても保存キーは変えていない）
- 問題数や単元の埋まり具合は変動するのでここには書かない。
  最新の内訳は `node validate-questions.js` の出力（先頭行）で確認する

## 問題を追加するとき

1. questions.js の `PRELOAD` を編集する（既存単元への追加は末尾に足す。
   末尾追加なら既存の学習履歴に影響しない）
2. `node validate-questions.js` を実行して検証する
3. index.html のフッターの更新日時を直す
4. **sw.js の `CACHE_NAME` を上げる**（上げないとService Workerが更新されず、
   ブラウザに反映されない）
5. push する

問題の書き方・単元の区切り方は CLAUDE.md を参照。

## 検証スクリプト

```
node validate-questions.js
```

チェック項目は、JSONとして読めるか / 必須キーの有無 / 選択肢がちょうど4個 /
同一問題内の選択肢重複 / 同一教科内の問題文重複 / 単元名の重複 / 想定外の文字の混入。
数式・座標に使う記号の全角は、違反ではなく警告として出す。
重複は「教科 / 単元 / 単元内の問題番号」で報告する（`PRELOAD` が1行のため行番号は使えない）。

終了コードは 0=全項目パス、1=違反あり、2=読み込み失敗。

合格の目安は**全項目パス（終了コード 0）**。重複が報告された場合、その問題は
アプリ側で排除されて出題されないため、解消してから push すること。

JSONの構文を壊すとアプリが白画面になるため、pushの前に必ず実行すること。
